# 管理アプリ統合（2026-10-24）

既存のMLX起動スクリプトへ、独立したローカルアプリで使用していた管理機能を統合した。既存 `models.conf` とモデルキャッシュは維持する。

- 管理のHTTP待受、token認証、要求の直列化、変更通知はSwift。
- モデル操作は既存Pythonの保護処理を都度実行する。常駐Python HTTPサーバーと旧実装への自動フォールバックは削除。
- 定期ポーリングと手動状態更新ボタンは設けない。初回・再表示のsnapshotと、API操作・ファイル・プロセスの変更通知で更新する。
- CLIは管理アプリと同じ起動記録を作り、標準出力を維持しながらログを記録する。execでPIDを維持し、外部停止もOS通知で検出する。
- 新しいSwiftプロセスの起動完了はstdoutの通知で受け取る。待受開始を繰り返し問い合わせない。
- 特定の個人フォルダを自動探索せず、ランチャー・Python・任意のGGUF連携先をビルド時に指定する。
- push / PRの既存CIを拡張し、管理機能のPython・JavaScript・SwiftテストとmacOSアプリビルドを追加。

READMEの画面は提供されたスクリーンショットへ差し替えた。MLXによる推論と、別途設定した外部GGUFランチャーの機能範囲を分けて記載している。

## 検証

- 公開コードのPython / Swiftテスト98件、JavaScriptテスト20件を確認した。
- macOS 14を最低対応版とする最適化ビルドとad hoc署名検証を完了した。
- 公開コードから更新した実アプリで、管理APIによるGemma GGUFの起動・停止を画面操作なしで反映した。
- 既存CLIによるGemma E2Bの起動と、同じPIDへの外部SIGTERMを画面操作なしで反映した。両経路で8080の `/v1/models` 応答も確認した。
- 検証用モデルと管理アプリを終了し、対象PIDの終了と8080 / 8766の解放を確認した。モデルの削除は行っていない。

GitHub Actionsの実行結果は[CI履歴](https://github.com/yukincom/mlx-model-switcher/actions/workflows/ci.yml)で確認できる。
